# Defining targets

## Anatomy of `tar_target()`

```r
tar_target(
  name,                     # unquoted symbol
  command,                  # R expression
  pattern = NULL,           # dynamic branching
  format = "rds",           # storage format
  memory = "auto",          # auto | transient | persistent
  retrieval = "auto",       # auto | worker | main | none
  storage = "worker",       # worker | main | none
  error = "stop",           # stop | continue | null | abridge | trim
  cue = NULL,               # tar_cue() overrides
  description = NULL        # free-form label
)
```

A target should:

- Return a single saveable value.
- Have no side effects, except when `format = "file"`.
- Be large enough to benefit from skipping.
- Be small enough that some can skip while others run.

## Storage formats

Set a default globally, override per target when needed:

```r
tar_option_set(format = "qs")
```

### Built-in formats

| Format | Serializer | When to use |
|--------|-----------|-------------|
| `"rds"` | `saveRDS()` | Default fallback |
| `"qs"` | `qs2::qs_save()` | Any R object — faster than `"rds"` |
| `"auto"` | `"file"` if target returns existing paths, else `"qs"` | Convenience; avoid for 10k+ targets |
| `"file"` | None (target returns paths) | External files produced by target |
| `"url"` | None (target returns URL) | Remote input tracked by ETag |
| `"feather"`, `"parquet"` | arrow | Data frames |
| `"fst"`, `"fst_dt"`, `"fst_tbl"` | fst | Data frames (fastest on single machine) |

**Notes on `format = "qs"`**: uses `qs2` for saving (targets >= 1.8.0.9014). Reads fall back to `qs::qread()` for older data, so upgrades are safe.

**`format = "file_fast"` is deprecated** (targets 1.10). `format = "file"` now automatically picks the timestamp strategy based on the file system.

**Custom formats** should be built with `tar_format()` and live in extension packages (e.g. `tarchetypes::tar_format_nanoparquet()`, `geotargets`). One gotcha if you write one yourself: the `convert()` function's return value is used both for change detection *and* as the value handed to `write()` — if those two need to differ (e.g. you want to hash a cheap summary but write the full object), you can't do it inside `convert()` alone.

### tarchetypes format factories

These are shorthand for `tar_target(..., format = "X")`:

| Factory | Equivalent | Requires |
|---------|------------|----------|
| `tar_rds()` | `format = "rds"` | base |
| `tar_qs()` | `format = "qs"` | qs2 |
| `tar_file()` | `format = "file"` | — |
| `tar_url()` | `format = "url"` | — |
| `tar_parquet()` | `format = "parquet"` | arrow |
| `tar_arrow_feather()` | `format = "feather"` | arrow |
| `tar_nanoparquet()` | `tar_format_nanoparquet()` | nanoparquet |
| `tar_fst()` / `tar_fst_dt()` / `tar_fst_tbl()` | `format = "fst*"` | fst |

`tar_nanoparquet()` is a lightweight alternative to `tar_parquet()` that skips the `arrow` dependency.

`tar_file_fast()` still exists in tarchetypes but wraps a deprecated format — prefer `tar_file()`.

## Tracking external files

### Read an input file (one step)

```r
tar_file_read(
  raw_data,
  "data/input.csv",
  read = readr::read_csv(!!.x, show_col_types = FALSE)
)
```

This creates two targets: `raw_data_file` (tracks the path) and `raw_data` (reads it). The `!!.x` placeholder is the file path, substituted by tarchetypes.

### Known-input dynamic branching

For a fixed list of files that exist before the pipeline runs:

```r
tar_files_input(
  data_files,
  files = c("data/a.csv", "data/b.csv", "data/c.csv"),
  batches = 2
)
```

Cheaper than `tar_files()` because it does not re-run every `tar_make()`.

### Files generated by a command

```r
tar_files(output_files, generate_output_paths())
```

Reruns on every `tar_make()` to detect whether the list of paths changed.

### Downloading with change tracking

```r
tar_download(
  remote_data,
  urls  = c("https://example.com/data.csv"),
  paths = c("data/downloaded.csv")
)
```

Uses ETag / Last-Modified to avoid re-downloading unchanged data.

## Function design

```r
# R/clean.R
clean_data <- function(raw) {
  raw |>
    filter_out(is.na(value)) |>
    mutate(date = as.Date(date))
}
```

- Take inputs as arguments, not globals.
- Return values; avoid side effects.
- Keep functions self-contained so hashing picks up all their dependencies.

**Closures hide code** from `targets`' static analysis. `purrr::safely()`, `Vectorize()`, and `Rcpp::cppFunction()` wrap your function in an opaque object. Wrap them in a named R function:

```r
safe_fit <- function(data) {
  purrr::safely(fit_model)(data)
}
```

**Don't return live resources as a target's value.** Database connections, API clients, external pointers, open file handles — anything that wraps a socket or a C-level resource doesn't survive `targets`' serialize-to-disk-and-reload cycle reliably, even when it doesn't error outright. A cached connection object can also just be stale by the time a downstream target reads it (expired token, closed session). Store the connection *parameters* as the target instead, and open the connection inside each target that actually needs it:

```r
# Fragile: caches a live API client as a target's stored value
tar_target(api_client, connect_to_api(key)),
tar_target(result, query(api_client, "endpoint")),

# Sturdier: the target stores parameters; each consumer connects itself
tar_target(api_key, Sys.getenv("API_KEY")),
tar_target(result, query(connect_to_api(api_key), "endpoint")),
```

If reconnecting per-target is genuinely expensive, that's a real tradeoff worth making deliberately — just don't do it by accident because it looked like a normal target.

## Options that matter

```r
tar_option_set(
  packages = c("tidyverse"),
  imports  = c("mypackage"),   # track function changes in a package
  format   = "qs",
  error    = "trim",
  seed     = 2026
)
```

Two utilities added in 1.11–1.12:

- `tar_option_unset("controller")` removes an option.
- `tar_option_with(list(error = "stop"), tar_make())` temporarily overrides options inside an expression.

## Cues

Override the default "rerun if anything changed" logic:

```r
tar_target(
  expensive,
  slow_computation(x),
  cue = tar_cue(mode = "never")  # only run when manually invalidated
)

tar_target(
  always_fresh,
  system2("curl", c("-s", url)),
  cue = tar_cue(mode = "always")
)

tar_target(
  post_paths,
  list.files("posts", full.names = TRUE),
  cue = tar_cue(mode = "always")
)
```

`always` earns its keep on two different kinds of target: a live external call you deliberately want re-checked every run (`always_fresh` above), and a *discovery* target like `post_paths` — a directory's contents aren't an R object `targets` can hash as a dependency the way a value or a tracked file is, so scanning it needs to happen on every `tar_make()` just to find out whether there's anything new. Either way, `always` only forces the target itself to rerun; anything downstream still skips normally if what it returns is unchanged — a `pattern = map(post_paths)` branching target rebuilds only the branches for paths that are actually new or changed, not the whole set, as long as `post_paths`' returned vector is otherwise the same.

Invalidate manually:

```r
tar_invalidate(expensive)
tar_make()
```
